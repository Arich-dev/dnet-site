Если что-то не работает

Сначала откройте окно DNet → вкладка «Журнал» или запустите с --debug: журнал честно говорит, что узел видит и почему отвергает пакеты.

Узел не запускается

«Не удалось занять порт. Уже запущен другой узел?» — порт 8765, 48555 или 48556 занят. Чаще всего это уже запущенный DNet (значок в трее). Если порт занят другой программой, поменяйте DNET_API_PORT (и адрес в расширении); DNET_UDP_PORT и DNET_TCP_PORT менять нельзя, если хотите видеть остальных (они используют стандартные).

Окно не открывается, пишет про Tk. В Linux поставьте sudo apt install python3-tk. Без окна всегда работают консоль и --no-ui.

Значка в трее нет. В Windows проверьте скрытые значки (стрелка ^ рядом с часами) и перетащите значок на панель. В Linux нужны pip install pystray pillow. В macOS значка нет.

Соседи не находятся

  1. Брандмауэр. Разрешите UDP 48555 и TCP 48556 для частной сети. Команды — в INSTALL.md. Классический признак: вы видите соседа, а он вас — нет (или наоборот).
  2. Разные подсети / гостевая сеть / изоляция клиентов Wi-Fi. Маяк работает только в пределах одной подсети; точки доступа с включённой «изоляцией клиентов» блокируют обмен. Добавьте соседа вручную: «Настройки → Соседи вручную» (192.168.1.20 или …:порт).
  3. Разные сети (дом ↔ дача). Через интернет без белого адреса узлы не найдут друг друга; нужен проброс порта TCP 48556 и static_peers с внешним адресом.
  4. VPN. Если трафик локальной сети уходит в VPN, соседи пропадут. Отключите VPN или исключите локальную подсеть.
  5. Проверка вручную: Test-NetConnection 192.168.1.20 -Port 48556 (PowerShell) — должно быть True.

Страницы не сохраняются

  • Расширение выключено (бейдж OFF на значке) или узел не запущен — в окне расширения узел должен быть «работает».
  • Страница не из публичной сети или попала под правило приватности: поиск, адреса с ?…, почта, вход, кабинеты, корзина, инкогнито. Это сделано специально.
  • Адрес узла в расширении не совпадает с реальным портом («Адрес узла» в окне расширения).
  • Расширение сохраняет страницу не чаще чем раз в 12 часов.

Страница не открывается при обрыве

  • Копии нет ни у вас, ни у соседей (узел пишет об этом в журнале: page … MISS).
  • Расширение подменяет только ошибки сети (нет интернета, DNS, таймаут, отказ соединения). Если сайт ответил любой страницей, в том числе ошибкой 500, подмены нет.
  • Узел должен быть запущен до обрыва: после обрыва расширение уже не сможет его разбудить.

Расширение

Firefox: «Расширение не может быть проверено». Обычный Firefox не принимает неподписанные расширения. Используйте «Загрузить временное дополнение» (about:debugging), либо Developer Edition / Nightly.

Chrome отключает расширение после перезапуска (из-за режима разработчика). Нажмите «Оставить» в предупреждении или установите его заново; для постоянной работы без предупреждения расширение нужно публиковать в магазине, это в планах.

Вкладка с копией пустая. Копия сохранена как есть: только HTML, без картинок, CSS и скриптов. Это ограничение выбрано ради малого размера кэша и безопасности.

Windows

SmartScreen / антивирус ругается на exe. Сборки не подписаны. Сравните SHA-256 с указанным на странице «Скачать» или соберите сами (python packaging/build_windows.py).

Автозапуск не работает. Проверьте: DNet.exe --autostart status. Если автозапуск включён, но программа не стартует, посмотрите, не отключил ли её «Диспетчер задач → Автозагрузка» (там она числится как «DNet»).

Как удалить полностью. «Параметры → Приложения → DNet → Удалить», при удалении отметьте очистку данных; для портативной версии просто удалите папку.

Роутер

См. раздел «Как проверить» в ROUTERS.md. Если на роутере dnetd: not found или Exec format error, взят бинарник не под ту архитектуру (mips ↔ mipsel — частая путаница; install.sh определяет сам).

Сообщить об ошибке

Приложите версию (DNet --version), систему, последние строки журнала (~/.dnet/debug.log при --debug) и что вы делали.
